#### OQ-22 ✅ **已裁决（2026-10-13）** —— 服从运行时 **Jackson `NON_NULL`** 现状

| 项 | 内容 |
| --- | --- |
| **问题** | 响应中 `null` 字段是省略还是返回 `null`？ |
| **裁决结论** | **服从运行时现状**。由于后端全局配置了 Jackson `NON_NULL`（`application.yml` `spring.jackson.default-property-inclusion: non_null` + `JacksonConfig` `Include.NON_NULL`），**当字段值为 `null` 时，该字段会从 JSON 响应中省略**。**前端 TypeScript 类型应将相应字段标记为可选（`?`），并针对字段缺失做容错处理。** |
| **依据** | ① **不修改 Java 代码 / 配置**（本次红线）；② 改全局序列化策略需回归全部 99 个 schema，收益与成本不匹配；③ 前端类型配置为可选 + `required` 字段恒有值即可完全等价；④ 可减少 20–30% 响应体积 |
| **强制补偿约定** | **C1** `required` 字段永不为空值；**C2** 前端类型标记为 `field?: T`（**不是** `T \| null`），禁止 `field!`；**C3** 读取前必须判空（可选链 / `??`）；**C4** 判定无数据**必须**用 `field === undefined`，**禁止** `field === null`（恒为 `false`）；**C5** 空集合 `[]` **必须返回**（配置为 `NON_NULL` 而**非** `NON_EMPTY`） |
| **落地文档** | [`data-conventions.md`](./data-conventions.md) §1（裁决结论 + 5 条强制约定）、[`notification-events.md`](./notification-events.md) §7（示例改为省略形态）、[`defaults-and-boundaries.md`](./defaults-and-boundaries.md) §3 |
| **影响面** | **全部 99 个 schema 的序列化行为**、前端类型定义与所有解构/取值代码 |
| **是否需变更契约** | **否**（`openapi.yaml` 的 `nullable: true` 只声明"值可为 null"，与"字段是否省略"并不冲突） |
| **裁决状态** | ✅ **已裁决** |
