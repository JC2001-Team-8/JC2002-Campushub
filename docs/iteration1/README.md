## 1. 本迭代在做什么（一段话）

本平台面向**高校校区及周边社区**的师生与居民，解决闲置物品在熟人半径内难以低成本、低信任门槛流转的问题：卖家挂出闲置，按**预设交易区域 + 公共取货点**完成线下当面交付；买家可**直接购买**，也可用自己的闲置**以物换物**。平台不读定位、不填住址、不做地图、不做物流。迭代一**只做需求、设计、工程骨架与接口清单**，不实现前端可点击原型、不写业务逻辑、不写使用说明书，目标是**冻结范围与契约，让团队能直接开始编码**。

## 4. 角色与权限速览

| 角色 | 一句话职责 | 核心限制 |
| --- | --- | --- |
| 访客 | 按分类浏览商品列表与详情 | 不能做任何写操作 |
| 注册用户 | 全平台个人能力的基础角色 | 必须登录；受处罚时写操作被禁 |
| 卖家 | 在其自有商品上发布、编辑、下架、设置交换状态 | 仅本人；占用态禁改关键字段 |
| 买家 | 加购、下单、付款、选点、确认收货、发起交换 | 仅本人；不可加自家商品 |
| 管理员 | 搜索用户、下架违规商品、封禁三天、查看处罚记录、处理申诉 | **不参与交易**；治理动作必须填原因并留审计 |
| 被处罚用户 | 可登录、浏览、查看自己的处罚与订单、提交申诉 | 交易类写操作禁止；到期自动解封 |
| 系统定时任务 | 超时取消、过期释放、自动解封、关闭评价窗口 | 无人工入口；全部必须幂等 |

**三条硬性边界**：① 管理员不参与交易；② 本人原则（归属校验失败返回 403 而非 404）；③ 处罚期间仍可登录与申诉。

## 5. 状态与规则速览

### 5.1 六大数据状态机

| 状态机 | 状态数 | 终态 | 超时转换 |
| --- | --- | --- | --- |
| 商品 | 7（草稿/在售/已预订/交换中/已售出/已下架/违规下架） | 已售出、违规下架 | — |
| 订单 | 6（待付款/已付款/已交付待确认/已完成/已取消/超时取消） | 已完成、已取消、超时取消 | 待付款 30 分钟 → 超时取消 |
| 交换提议 | 7（待处理/已接受/已拒绝/已反提案/已过期/已取消/已完成） | 已完成、已拒绝、已过期、已取消 | 待处理 72 小时 → 已过期 |
| 交换包 | 6（草稿/已打包/交换中/已占用/已释放/已完成） | 已完成 | — |
| 处罚 | 4（生效中/申诉中/已解封/已过期） | 已解封、已过期 | 到期 → 已过期（自动解封） |
| 申诉 | 3（已提交/申诉通过/申诉驳回） | 申诉通过、申诉驳回 | — |

### 5.2 五条最关键的规则

| 规则 | 一句话 |
| --- | --- |
| R-16 库存占用与释放 | 下单即占用（不是付款时占用），取消/超时/违规下架时释放；一物同时只能被一笔未终结订单占用 |
| R-18 并发控制 | 一律条件更新或乐观锁，禁止「先查后改」；并发冲突返回 409 + 当前状态 |
| R-22 整包接受 | 交换是 all-or-nothing，**不支持部分接受**；想要部分只能反提案 |
| R-24 整笔作废 | 交换涉及商品中任意一件被占用/下架，**整笔作废**并释放全部占用 |
| R-31 自动解封 | 封禁固定 3 天，到期定时任务自动解封，与手动解封/申诉通过并发时只允许一个成功 |
