## 1. 图例与约定

### 1.1 记号

| 记号 | 含义 |
| --- | --- |
| ✅ | 允许 |
| ❌ | 禁止 |
| 🔒 | 允许，但**必须登录** |
| 👤 | 允许，但**必须是本人**（资源 owner / 交易参与方） |
| 🛡️ | 仅管理员（ROLE_ADMIN） |
| ⛔ | 被处罚用户在处罚有效期内**禁止** |
| ⏱️ | 由系统定时任务执行，无人工调用入口 |
| — | 不适用（该角色语义上不涉及此操作） |

> 复合记号示例：`🔒👤⬛` 表示「必须登录 + 必须本人 + 被处罚用户禁止」。

### 1.2 列（角色）

| 列 | 角色 | 定义 |
| --- | --- | --- |
| 访客 | ROLE_GUEST | 未登录用户，只读 |
| 注册用户 | ROLE_USER | 已登录的普通用户（未涉及具体交易身份时的通用能力） |
| 卖家 | ROLE_SELLER | 注册用户**在其自有商品/其作为卖方的订单**上的关系角色 |
| 买家 | ROLE_BUYER | 注册用户**在其作为买方的订单/其发起的交换**上的关系角色 |
| 管理员 | ROLE_ADMIN | 治理角色，不参与交易 |
| 被处罚用户 | ROLE_RESTRICTED | 处于生效中处罚的用户，交易写操作被禁 |
| 系统 | ROLE_SYSTEM | 内置定时任务 |

### 1.3 三条硬性边界（先于矩阵，优先级最高）

| 编号 | 边界 | 说明 |
| --- | --- | --- |
| P-00-A | **管理员不参与交易** | ROLE_ADMIN 对任何购买/交换/发布商品操作一律 ❌，即使技术上其账号可登录 |
| P-00-B | **本人原则** | 涉及「自己的资源」的操作必须校验资源归属，仅靠登录态不足；校验失败返回 403（禁止）而非 404 |
| P-00-C | **处罚不越权** | 被处罚用户仍可登录、浏览、查看自己的处罚与提交申诉；只禁止**交易类写入**（见 §8） |

| 加购物车 / 下单 / 付款 | ⛔ | 禁止 |
| 创建交换包 / 发起交换 / 接受 / 反提案 | ⛔ | 禁止 |
| 卖家交付 / 买家确认收货 | ⛔ | 禁止（处罚不阻断**已存在**订单的收尾：见 Q-13） |
| 评价 | ⛔ | 禁止 |

> **重要边界（待确认 Q-13）**：处罚是否影响**处罚前已存在**的进行中订单/交换？本迭代假设为**不影响已完成收尾流程所需的确认操作**，否则交易会永久卡死。该点必须在接口契约冻结前确认。

## 9. 权限实现要点（供接口契约使用）

| 编号 | 要点 | 契约要求 |
| --- | --- | --- |
| PERM-01 | 所有受保护接口必须声明所需角色与归属校验 | 接口清单中每行必须有「权限」列，取值来自本矩阵记号 |
| PERM-02 | 归属校验失败统一返回 **403**，不返回 404（避免信息泄露与语义混淆） | 统一错误语义 |
| PERM-03 | 被处罚用户的拦截应返回**专用错误**并携带解封时间 | 便于前端提示 |
| PERM-04 | 管理员接口不参与交易鉴权链路（P-00-A） | 防止权限串用 |
| PERM-05 | 幂等要求独立的接口（下单、付款、发起交换、接受、确认收货、封禁、解封）必须在接口契约中显式标注 | 见 `rules.md` §3 |
| PERM-06 | 治理类接口**必须**包含 `reason` 字段（封禁/下架/申诉处理） | 审计与申诉举证 |
| PERM-07 | 定时任务不暴露公开 HTTP 接口；如需手动触发，仅管理员且标注为运维用途 | 避免误触发 |
