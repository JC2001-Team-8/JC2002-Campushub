## 1. 编号规则与处理原则

| 项 | 说明 |
| --- | --- |
| 编号 | `AQ-xx`（API Question），与需求侧 `Q-xx`、数据库侧 `DQ-xx` 独立，避免混淆 |
| 原则 1 | **不扩大范围**：本文件只登记「冻结契约时必须做出选择」的点，不新增业务功能 |
| 原则 2 | **已给出可执行默认值**：每个问题都已有落地实现（否则契约无法冻结），确认后可低成本调整 |
| 原则 3 | **集中登记**：任何在 `openapi.yaml` 或契约文档中出现的假设，必须在此登记，不得只写在 `description` 里 |
| 原则 4 | 涉及**破坏性变更**的确认结果，须走 [api-freeze.md](./api-freeze.md) §4 变更流程 |
| 优先级 | **P0** = 阻塞契约评审通过；**P1** = 阻塞后端实现；**P2** = 可延后，不阻塞 |

## 3. 契约阶段的设计决策（AD 系列）

> 这些是**为避免歧义而主动做出的契约设计选择**，登记备查。如需调整，按变更类型走流程。

| 编号 | 决策 | 理由 | 影响 |
| --- | --- | --- | --- |
| **AD-01** | 统一响应包络 `ApiResponse`，**成功 `code` 固定为 `OK`**，业务失败一律用非 2xx HTTP 状态码 + `ErrorResponse` | 避免「HTTP 200 + 业务错误码」的混用模式导致前端判定混乱 | 所有接口 |
| **AD-02** | **越权返回 403，不用 404** | E-02 明确要求；避免用 404 掩盖越权，也避免资源存在性泄露 | 全部涉及归属校验的接口 |
| **AD-03** | 错误码格式 `DOMAIN_REASON`，前端**必须按 `code` 分支**，不得匹配 `message` | `message` 是文案，会优化；`code` 才是稳定契约 | 全部错误处理 |
| **AD-04** | 金额使用 `DecimalString`（十进制字符串）而非 JSON number | 对应数据库 `numeric(12,2)`，**避免浮点误差**；R-13 估价仅展示 | 全部金额字段 |
| **AD-05** | 时间统一 ISO 8601 **UTC**；倒计时同时返回 `expiresAt`（绝对）与 `remainingSeconds`（服务端算） | R-19：服务端时间为准，**禁止前端自行推算** | 订单/提议/处罚的倒计时 |
| **AD-06** | 分页 `page` **从 0 开始**，`sort` 形如 `字段,方向` | 与后端分页惯例一致；白名单可解释排序（OOS-09 不做个性化） | 全部分页接口 |
| **AD-07** | 请求 DTO 与响应 DTO **分离**，请求体不复用数据库实体 | 避免暴露 `password_hash`/`deleted_at` 等内部字段；避免请求侧可写只读字段 | 全部写接口 |
| **AD-08** | 敏感字段一律不出现在 Schema 中（`password_hash`、`deleted_at`、`created_by`、`updated_by`、`request_hash`） | 验收要求；安全要求 | 全部 Schema |
| **AD-09** | 枚举取值**逐字对齐** `V1__init_schema.sql`，契约不新增未登记枚举 | 验收要求 7；避免 API 与数据库枚举漂移（已校验 21/21 一致） | 全部枚举 Schema |
| **AD-10** | 「卖家 / 买家」以**关系角色**字段（`role: BUYER / SELLER`）表达，而非独立角色枚举 | 继承决策：卖家/买家**不是注册身份** | `OrderSummary.role`、`OrderDetail.role`、`SwapProposalSummary.role` |
| **AD-11** | 管理员**不参与交易**：`x-required-roles` 中 ADMIN 不出现在任何交易类操作上 | P-00-A；避免治理权限与交易身份混淆 | 交易类操作 |
| **AD-12** | 权限用 `x-required-roles` 扩展 + `description` **双写** | 扩展便于工具化校验；description 便于人读 | 全部操作 |
| **AD-13** | 幂等要求用 `x-idempotency` + 复用参数 `IdempotencyKeyRequired/Optional` **双声明** | 参数决定工具生成；扩展便于清单统计 | 32 个写操作 |
| **AD-14** | 并发语义用 `x-locking` 扩展显式声明条件更新表达式 | R-18 要求可被工具/评审直接看到，而非散落在文字里 | 状态转换类操作 |
| **AD-15** | **整包接受接口不接受物品子集参数**（`acceptSwapProposal` 无请求体物品列表） | 从接口形状上杜绝「部分接受」（OOS-04 / R-22），而非仅靠文档禁止 | `acceptSwapProposal` |
| **AD-16** | 举报重复提交返回 **200 + 既有记录**（而非报错） | E-14 要求幂等；用户体验上「已举报」视为成功 | `reportItem` |
| **AD-17** | 幂等命中（E-06）返回**首次结果**（200/201），不返回错误 | R-17 IDEM-A 语义 | 16 个必填幂等接口 |
| **AD-18** | 内部接口前缀 `/internal/`，使用独立 `internalToken` 方案 | FR-601~FR-604 不应对外暴露；与用户 JWT 解耦 | 4 个定时任务接口 |
| **AD-19** | 字典与区域接口**公开可访问**（无需登录） | 访客需能浏览并看到商品所在区域；且注册流程需要区域列表 | #12~#15 |
| **AD-20** | `refreshToken` 未启用时返回 **501** 而非删除接口 | 保留契约形状，Q-07 确认后仅切实现开关，**无需变更契约** | `refreshToken` |
