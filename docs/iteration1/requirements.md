## 1. 项目定位与迭代一目标

### 1.1 一段话定位

本平台面向**高校校区及周边社区**内的师生与居民，解决「闲置物品在熟人半径内难以低成本、低信任门槛地流转」的问题：卖家可以把闲置物品挂出来，按**预设的校区/社区交易区域 + 公共取货点**完成线下当面交付，买家可以**直接购买**，也可以用自己的闲置物品**发起以物换物**。平台不涉及物流、不读定位、不填住址、不做地图导航，全部交易发生在用户自己勾选的常用交易区域内的公共取货点，用「固定取货点 + 交换码/交付确认」替代复杂的地理与信任基础设施。

### 1.2 服务对象

- 主要服务对象：**2–3 个校区**内的在校学生、教职工，以及校区**周边社区**的居民。
- 服务范围是**有限地理半径**（同一交易区域），不做全国/跨城交易。
- 具体校区与周边社区名称：**待用户确认**（见 §2.1，本文给出 3 组候选）。

### 1.3 迭代一交付边界

迭代一**只做需求、设计、工程骨架和接口清单**，具体交付与非交付如下：

| 类别 | 迭代一交付 | 迭代一不交付 |

| 接口 | 接口清单（资源、方法、路径、权限、幂等要求、错误场景、冻结基线），**10/9 后不许新增** | OpenAPI YAML/JSON 文件、接口实现代码 |

### 2.1 候选校区与周边社区【待用户确认】

| 候选组 | 校区 | 周边社区（示例） | 建议理由 | 状态 |
| --- | --- | --- | --- | --- |
| 候选组 A | 【待确认】XX大学（主校区） | 【待确认】校区东门外住宅区、教工家属区 | 学生密度高、单一校区管理半径小，最容易跑通闭环 | 待用户确认 |
| 候选组 B | 【待确认】XX学院（南校区） | 【待确认】南苑小区、青年公寓 | 校区与社区物理相邻，可验证「校内+社区」混合交易 | 待用户确认 |
| 候选组 C | 【待确认】XX职业技术学院 | 【待确认】职教园区宿舍区、周边商业街区 | 生活半径集中，公共取货点易定义 | 待用户确认 |

**范围冻结规则（迭代一）**：

1. 最终只保留 **2–3 个校区**及其周边社区，超出范围的地理区域**不支持注册选择、不支持发布商品**。
2. 「校区/社区」即本平台的**交易区域（TradeZone）**，是权限校验、搜索过滤、公共取货点归属的最小地理单位。
3. 一个用户可勾选**多个**常用交易区域（1–5 个），但下单/发起交换时商品与订单必须落在**同一**交易区域内。
4. 跨交易区域交易：迭代一**不做**（见 `out-of-scope.md` OOS-07）。

### 2.3 公共取货点类型

公共取货点（PickupPoint）归属于某个交易区域，是**线下当面交付**的约定地点。

| 取货点类型编码 | 类型名称 | 说明 | 适用场景 |
| --- | --- | --- | --- |
| PP-LIB | 图书馆门口 | 人流大、监控覆盖、白天可达 | 书籍、文具、小件 |
| PP-CANTEEN | 食堂门口 | 饭点人流集中、交付效率高 | 日用品、小件 |
| PP-TEACHING | 教学楼大厅 | 有遮挡、可短时停留 | 电子配件、书籍 |
| PP-DORM | 宿舍区门口 | 生活半径内、晚间可达 | 大件、生活用品 |
| PP-GATE | 校门口 | 校内外用户都能到达 | 社区用户参与的交换 |
| PP-SQUARE | 社区广场/活动中心 | 社区侧公共空间 | 社区用户之间的交易 |

**取货点规则**：

1. 取货点必须属于订单/商品所在的**同一交易区域**（`rules.md` R-05）。
2. 取货点由**买家在提交订单时或付款后选择**（本迭代定为付款后选择，见 `rules.md` R-06）。
3. 取货点具体名称与开放时间列表：**待确认问题 Q-03**。

## 3. 角色与权限主体

### 3.1 角色定义

| 角色编码 | 角色名称 | 获得条件 | 说明 |
| --- | --- | --- | --- |
| ROLE_GUEST | 访客 | 未登录访问 | 只读浏览；不做任何写操作 |
| ROLE_USER | 注册用户 | 注册并登录成功 | 一切个人操作的**基础角色**，含资料、购物车、下单、交换 |
| ROLE_SELLER | 卖家 | 用户发布商品后在其自有商品语义下获得 | **不是独立账号角色**，是「用户对自己商品」的关系角色 |
| ROLE_BUYER | 买家 | 用户提交订单/发起交换后获得 | 同上，是「用户对某笔订单/交换」的关系角色 |
| ROLE_ADMIN | 管理员 | 由系统预置账号授予（来源待确认 Q-04） | 治理类操作唯一执行者 |
| ROLE_RESTRICTED | 被处罚用户 | 被封禁后自动进入 | 仍可登录查看处罚与申诉，交易类写操作被禁止 |
| ROLE_SYSTEM | 系统定时任务 | 服务内置调度器 | 超时取消、过期释放、自动解封等，无人工身份 |

### 3.2 角色关系说明（重要）

- **卖家/买家不是注册时选择的身份**。任何注册用户都可以发布商品（在该商品上成为卖家），也可以下单或发起交换（在该笔交易上成为买家）。一个用户可以在 A 商品上是卖家、在 B 商品上是买家。
- **管理员与普通用户账号体系共用**，但管理员**不参与**交易链路（不得下单、不得发布商品），以避免治理权限与交易身份混淆。
- **被处罚用户不是永久角色**：封禁到期或申诉通过后自动回到 ROLE_USER。处罚期间账号可登录但受限。
- **系统定时任务不是用户**，其操作在审计日志中记为 `system`。

### 3.3 登录与身份校验要求

| 校验类型 | 含义 | 适用操作（摘要） |
| --- | --- | --- |
| 公开（无需登录） | 匿名可访问 | 浏览商品列表、商品详情、按分类筛选、查看卖家交换状态 |
| 必须登录 | 需要有效登录态 | 加购物车、下单、付款、取消、确认收货、评价、发布商品、创建交换包、发起交换、举报、勾选交易区域、修改资料 |
| 必须本人 | 登录且操作对象属于自己 | 编辑/下架自己的商品、取消自己的订单、确认自己订单的收货、接受/拒绝/反提案自己收到的交换提议、查看自己的交换码、确认自己的交换 |
| 仅管理员 | 需 ROLE_ADMIN | 搜索用户、下架违规商品、封禁、查看处罚记录、处理申诉 |
| 被处罚用户禁止 | ROLE_RESTRICTED 不可执行 | 发布/编辑商品、下单、付款、接受或发起交换、评价；**允许**查看处罚记录与提交申诉 |

详细矩阵见 `permission-matrix.md`。

### 3.4 审计主体

所有治理类操作（下架、封禁、解封、申诉处理）必须记录**操作者、操作时间、对象、原因、前后状态**，用于后续处罚记录与申诉举证。此要求直接约束后续接口契约（每个治理接口必须接受 `reason`）。

## 4. 功能范围

### 4.3 购买（FR-300 系列）

| 编号 | 需求 | 验收要点 |
| --- | --- | --- |
| FR-301 | 加入购物车 | 同一商品不可重复加入（已存在则数量不变或提示）；不能加自己发布的商品 |
| FR-302 | 购物车按卖家分组 | 购物车列表以卖家为分组展示，便于按卖家拆单 |

| FR-305 | 付款倒计时 | 下单成功后开始倒计时【假设 30 分钟】，前端展示「已为你保留，剩余 15:00 付款」 |
| FR-306 | 模拟付款 | 调用模拟付款接口，成功即订单变为「已付款/待取货」，**不接入任何真实支付** |
| FR-307 | 超时取消 | 倒计时归零后由定时任务取消订单并释放商品（幂等） |
| FR-308 | 主动取消 | 买家在待付款阶段可主动取消；已付款后取消**待确认**（假设：已付款不可自助取消，需管理员介入，Q-08） |

| FR-311 | 买家确认收货 | 仅买家本人可确认；确认后订单完成，商品状态置为已售出 |
| FR-312 | 互评前置条件 | 评价仅在订单「已完成」后开放；买卖双方各评一次，互评窗口【假设 7 天】 |

### 4.4 交换（FR-400 系列）

| 编号 | 需求 | 验收要点 |
| --- | --- | --- |
| FR-401 | 设置交换状态 | 卖家对每个商品设置「接受交换 / 不接受交换」 |
| FR-402 | 创建交换包 | 发起方将 **1–5 件**自己的商品打包成一个交换包；同一商品只能存在于一个**进行中**交换包 |
| FR-403 | 交换包估价合计 | 系统自动汇总包内商品估价，展示合计值（**仅展示，不自动判定等价，不做补差价**） |
| FR-404 | 发起交换 | 用整个交换包向**他人的单件或多件商品**发起交换提议；需指定交易区域与说明 |
| FR-405 | 整包接受 | 目标方可**整包接受**；接受后交换包内所有商品 + 目标商品同时被占用 |
| FR-406 | 拒绝 | 目标方可拒绝，提议终结，占用全部释放 |
| FR-407 | 反提案 | 目标方可不接受原包，而是提出自己的交换包作为反提案【**仅一轮**，假设 A-08】 |
| FR-408 | 72 小时过期 | 提议超过 72 小时未处理自动过期并释放占用（定时任务，幂等） |
| FR-409 | 交换码 | 提议被接受后生成交换码（一次性校验凭证），双方凭码完成线下交付 |
| FR-410 | 双方确认 | 双方各自确认已交付/已收到后，交换完成 |
| FR-411 | 同时占用 | **同一物品同一时间只能被一个进行中交换占用**（占用互斥，见 rules R-20） |
| FR-412 | 整笔作废 | 交换涉及的商品中**任意一件**被其他订单占用、被下架或违规下架时，**整笔交换作废**，全部占用释放 |

### 4.5 管理员治理（FR-500 系列）

| 编号 | 需求 | 验收要点 |
| --- | --- | --- |
| FR-501 | 搜索用户 | 按用户名/昵称/用户ID检索；分页；仅管理员 |
| FR-502 | 下架违规商品 | 管理员可下架任意商品并填写原因；商品状态置为「违规下架」 |
| FR-503 | 封禁三天 | 默认封禁 **3 天**（72 小时）；可指定？**假设固定 3 天不可调**（Q-09） |
| FR-504 | 查看处罚记录 | 按用户/时间/类型查询处罚历史；仅管理员可见全量，用户可见自己的 |
| FR-505 | 处理申诉 | 用户对被处罚提出申诉；管理员可「申诉通过（解封）/ 申诉驳回」 |
| FR-506 | 自动解封 | 封禁到期由定时任务自动解封（幂等，重复执行不产生重复记录） |
| FR-507 | 通知 | 治理动作产生站内通知给被处罚用户（渠道待确认 Q-05） |

## 5. 关键业务流程（需求视角摘要）

> 仅描述业务步骤，不涉及页面实现细节；页面清单见 `pages-and-flows.md`。

### 5.1 购买主线

```
浏览商品（访客可）→ 加入购物车 → 购物车按卖家分组 → 提交订单（整卖家一单）
→ 库存预留 + 倒计时 30:00 → 模拟付款 → 订单「已付款/待取货」
→ 选择公共取货点 → 卖家线下交付并标记「已交付」 → 买家确认收货
→ 订单「已完成」+ 商品「已售出」 → 双方互评
【分支】倒计时归零 → 超时取消 → 释放商品
【分支】买家主动取消（仅待付款）→ 释放商品
```

### 5.2 交换主线

```
卖家设置商品「接受交换」 → 发起方创建交换包（1–5 件自己商品，整包占用）
→ 向目标商品发起交换提议（72 小时有效） → 目标方：整包接受 / 拒绝 / 反提案
【接受】→ 双方商品同时占用 + 生成交换码 → 线下凭码交付 → 双方确认 → 交换完成
【拒绝】→ 提议终结，全部占用释放
【反提案】→ 生成反向提议（原提议置「已反提案」），一轮后仅可接受或拒绝
【超时】→ 72 小时过期，全部占用释放
【作废】→ 任一件商品被其他占用/下架/违规下架 → 整笔作废，全部占用释放
```

### 5.3 治理主线

```
管理员搜索用户 → 发现违规 → 下架商品（记原因）/ 封禁三天（记原因）
→ 用户收到站内通知 → 用户提交申诉 → 管理员处理申诉
【通过】→ 立即解封 → 处罚记录保留（结果=申诉通过）
【驳回】→ 处罚继续生效 → 到期自动解封 → 处罚记录保留（结果=已过期/已解封）
```

## 6. 关系图（文字化 ER 描述，非 SQL）

> 本节仅供数据库设计参考，**不含 DDL、不含 SQL**。字段为业务字段名（非物理列名）。

```text
User (用户)
 ├─ 1:N UserTradeZone        （用户勾选的常用交易区域，1–5 条）
 ├─ 1:N Item                 （作为卖家发布的商品）
 ├─ 1:N CartItem             （购物车条目）
 ├─ 1:N Order (as buyer)     （作为买家）
 ├─ 1:N Order (as seller)    （作为卖家，通过 OrderItem 关联）
 ├─ 1:N SwapBundle           （作为发起方创建的交换包）
 ├─ 1:N SwapProposal         （作为发起方 / 作为目标方）
 ├─ 1:N Report               （提交的举报）
 ├─ 1:N Penalty              （受到的处罚）
 └─ 1:N Appeal               （提交的申诉）

TradeZone (交易区域，预设)
 ├─ 1:N PickupPoint          （公共取货点）
 └─ 1:N Item                 （商品归属区域）

PickupPoint (公共取货点，预设，归属 TradeZone)
 └─ 1:N Order                （订单选定的取货点）

Item (商品)
 ├─ N:1 User (seller)
 ├─ N:1 Category             （预设分类）
 ├─ N:1 TradeZone
 ├─ 1:N ItemImage            （1–9 张）
 ├─ 0:N OrderItem            （被某笔订单占用/成交）
 └─ 0:N SwapBundleItem       （被放入某个交换包）

Order (订单)  —— 同一订单只含一个卖家
 ├─ N:1 User (buyer)
 ├─ N:1 User (seller)        —— 冗余，便于按卖家分组
 ├─ N:1 PickupPoint          （付款后选定）
 ├─ 1:N OrderItem            （订单明细）
 └─ 0:1 Review (buyer→seller) / 0:1 Review (seller→buyer)

OrderItem (订单明细)
 ├─ N:1 Order
 ├─ N:1 Item                 （同一 Item 同时最多被一笔未终结 OrderItem 占用）
 └─ 价格快照：估价快照、标题快照（防商品后续编辑影响历史订单）

SwapBundle (交换包)
 ├─ N:1 User (owner，发起方)
 ├─ 1:N SwapBundleItem       （1–5 件，均为 owner 的商品）
 └─ 0:N SwapProposal         （作为提议方交换包 / 作为反提案交换包）

SwapProposal (交换提议)
 ├─ N:1 SwapBundle (proposerBundle)
 ├─ N:1 User (proposer)
 ├─ N:1 User (target)
 ├─ 1:N SwapProposalTargetItem （目标方的被请求商品，≥1 件）
 ├─ N:1 TradeZone
 ├─ 0:1 SwapCode             （接受后生成，一次性）
 └─ 状态：PENDING/ACCEPTED/REJECTED/COUNTERED/EXPIRED/CANCELLED/COMPLETED

Report (举报)
 ├─ N:1 User (reporter)
 ├─ N:1 Item
 └─ 状态：PENDING/HANDLED/DISMISSED

Penalty (处罚)
 ├─ N:1 User (target)
 ├─ N:1 User (operator，管理员)
 ├─ 类型：BAN_3D / ITEM_TAKEDOWN（下架记为商品级处置，处罚记录可引用）
 ├─ 起止时间、原因、状态
 └─ 0:N Appeal

Appeal (申诉)
 ├─ N:1 Penalty / N:1 User
 └─ 状态：SUBMITTED/APPROVED/REJECTED
```

**关键约束（供数据库设计落地）**：

| 约束编号 | 约束 | 说明 |
| --- | --- | --- |
| C-01 | 一个 Item 同时最多被 **1 个进行中占用**（订单占用或交换占用） | 需唯一/排他约束或乐观锁 + 状态校验 |
| C-02 | 一个 Order 只包含 **1 个卖家** 的 OrderItem | 跨卖家提交时自动拆单 |
| C-03 | 一个 SwapBundle 含 **1–5** 件，且所有件属于同一 owner | 业务校验 |
| C-04 | 一个 SwapProposal 的目标商品 **≥1** 件，且全部属于同一 target | 业务校验 |
| C-05 | 一个 SwapProposal 同时最多 **1 个** SwapCode，且 SwapCode 一次性使用 | 唯一约束 |
| C-06 | 同一用户对同一 Item 的未处理举报最多 1 条 | 幂等约束 |
| C-07 | 被处罚用户在处罚有效期内不得产生新的交易类写入 | 应用层 + 状态校验 |

## 7. 错误场景与统一错误语义（需求级）

> 具体 HTTP 状态码与错误码字符串在接口清单中冻结，本节仅定义**必须覆盖的错误场景**。

| 场景编号 | 错误场景 | 期望行为 | 幂等/并发要求 |
| --- | --- | --- | --- |
| E-01 | 未登录访问受保护接口 | 返回未认证，前端跳登录 | — |
| E-02 | 访问他人资源（编辑他人商品、确认他人订单） | 返回无权限 | — |
| E-03 | 被处罚用户执行交易写操作 | 拒绝并提示处罚到期时间 | — |
| E-04 | 商品已被占用 / 已售出 | 拒绝加购、下单、发起交换 | 并发下必须只有一方成功 |
| E-05 | 订单已超时 / 已取消，重复付款 | 拒绝付款，保持终态 | 重复付款必须幂等失败 |
| E-06 | 重复提交订单 / 重复点击付款 | 第一次成功，后续返回相同结果或明确的「已处理」 | **幂等键必需** |
| E-07 | 交换包件数 <1 或 >5 | 拒绝并提示范围 | — |
| E-08 | 交换目标商品不接受交换 | 拒绝发起 | — |
| E-09 | 交换提议已过期/已终结，仍执行接受 | 拒绝并返回当前状态 | 并发接受只能一方成功 |
| E-10 | 同一商品被两笔交换同时请求 | 后到者失败，提示已被占用 | 排他占用 |
| E-11 | 交换中任一件商品被下架/违规下架 | 整笔交换作废，全部释放 | 作废只执行一次 |
| E-12 | 交换码重复使用 | 第二次校验失败 | 一次性 |
| E-13 | 管理员封禁一个已在处罚中的用户 | 拒绝或延长需明确语义【待确认 Q-10：假设拒绝】 | 不产生两条并存生效处罚 |
| E-14 | 重复举报同一商品 | 第二次返回「已举报」 | 幂等 |
| E-15 | 对未完成订单评价 | 拒绝 | — |
| E-16 | 定时任务重复执行 | 无副作用，不产生重复记录 | **全部定时任务必须幂等** |
